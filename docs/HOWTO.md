# Индексный фонд: недельная корзина с трендовым гейтом по BTC

## Что делает стратегия

Каждый месяц это отдельная папка `content/<mon>_<yyyy>/` с самодостаточным кодом: `main.strategy.ts` (стратегия и список тикеров месяца), `classes/YahooFinance.ts` (дневные свечи Yahoo Finance без ccxt) и `modules/backtest.module.ts` (адаптер биржи с маппингом `BASEUSDT` в `BASE-USD`, семплирование минуток из дневок, `CC_BACKTEST_STEP_MINUTES` на сутки и фрейм месяца). Общего кода между месяцами нет, папки штампуются копипастой из эталона.

Правила фонда, все константы в шапке `main.strategy.ts`:

- Депозит 1000 $ делится поровну между тикерами корзины месяца.
- Корзина месяца: топ-20 USDT-пар спота Binance по обороту за предыдущий месяц. Список известен до начала месяца, заглядывания вперёд нет. Исключены стейблкоины, плечевые токены, обёртки BTC/ETH и листинги моложе 90 дней.
- Гейт: доля окон 20, 25, 30, 35, 40, 45 дней, на которых BTC вырос. Это экспозиция корзины от 0 до 1, остаток депозита уходит в PAXGUSDT (золото).
- Каждая позиция живёт неделю и закрывается по времени, затем перезаход на первом тике после закрытия. Стоп −50% и тейк +500% технические, за неделю на споте недостижимы.
- Свечи дневные с Yahoo Finance, по одному запросу на тикер; минутки для симуляции семплируются из дневного бара, внутри дня движения нет, позиции оцениваются раз в сутки. Список тикеров месяца определяет, какие ряды будут скачаны. Mongo хранит только сигналы и состояние, свечи в него не пишутся.

Ограничение движка: общего депозита между символами нет, каждый символ это независимый бэктест, вес задаётся через `cost` сигнала. `cost: 0` движок молча заменяет на 100 $, поэтому нулевая доля это `null` вместо сигнала.

## Подготовка

```bash
npm install
docker compose -f docker/mongo/docker-compose.yaml up -d
docker compose -f docker/redis/docker-compose.yaml up -d
```

Mongo и Redis обязательны: `config/loader.config.ts` ждёт их подключения до загрузки стратегии, хотя свечи в Mongo больше не пишутся. Пароль Redis из `docker/redis/docker-compose.yaml` задаётся переменной `CC_REDIS_PASSWORD` в `.env`.

## Пересборка списков тикеров и папок месяцев

```bash
node scripts/common/build_universe.mjs --top 20 --from 2020-09 --to 2026-09
node scripts/common/resolve_yahoo_tickers.mjs
node scripts/common/build_universe.mjs --top 20 --from 2020-09 --to 2026-09
node scripts/common/generate_months.mjs --source content/sep_2020
```

Первая команда качает месячные свечи всех USDT-пар Binance (кэш в `tmp/`, `--refresh` обновляет) и ранжирует их по обороту в `scripts/common/universe.json`. Вторая находит для каждой монеты тикер Yahoo: обычно `BASE-USD`, для одноимённых токенов тикер с числовым суффиксом через поиск Yahoo, а монеты без котировок на Yahoo помечаются `null` в `scripts/common/yahoo_tickers.json`. Повторная сборка вселенной исключает такие монеты из корзин, поэтому порядок именно такой. Генератор копирует эталонную папку во все месяцы, подставляя блок `BASKET:BEGIN..BASKET:END` в стратегии, блок `TICKER_OVERRIDES` и фрейм в модуле биржи, копирует `classes/` и переписывает раннеры `scripts/linux/generate_strategy.sh` и `scripts/win/generate_strategy.bat`.

Чтобы изменить стратегию, правьте эталон `content/sep_2020/main.strategy.ts` и запускайте генератор заново.

## Мультиактивный портфель: `content/multi_asset/`

Отдельная папка по тому же образцу, один длинный фрейм с 2015 года по дневным тикам. Четыре инструмента, по одному на класс активов: BTCUSD, GOLD (фьючерс COMEX), SPX, TLT. Веса по равному вкладу в риск из ковариации дневных доходностей за 90 дней, крипто-нога дополнительно умножается на тот же гейт по BTC, освободившаяся доля раздаётся остальным классам. Удержание неделя, перезаход на следующем дневном тике.

Свечи без ccxt: `classes/YahooFinance.ts` качает дневные бары с Yahoo Finance chart API по требованию, один запрос на тикер за 15 лет. Адаптер биржи в `modules/backtest.module.ts` отдаёт дневные запросы через `getCandlesFilled`, а всё короче дня через `getCandlesSampled`, который размножает дневной бар на минуты. Внутри дня у таких свечей нет движения, поэтому стратегия ставит `CC_BACKTEST_STEP_MINUTES: 24 * 60` и движок оценивает позиции раз в сутки, одиннадцать лет проходят за минуты. Запись свечей в Mongo для этого адаптера выключена через `PersistCandleAdapter.useDummy()`, в отчёте оставлены только `opened` и `closed`.

```bash
npm start -- --backtest --entry ./content/multi_asset/main.strategy.ts
```

Известное допущение семплирования: high, low и close дневного бара известны только к концу дня, а семплированные минутки несут их с утра. Для недельного удержания с выходом по времени это не влияет на результат, для внутридневных стопов влияло бы.

## Прогон

Один месяц:

```bash
npm start -- --backtest --entry ./content/sep_2020/main.strategy.ts
```

Все месяцы подряд:

```bash
bash scripts/linux/generate_strategy.sh
```

Отчёт месяца: `content/<месяц>/dump/report/backtest.jsonl`, строки `opened`, `active` и `closed` по каждому сигналу; `closeReason: "time_expired"` это штатный недельный выход. В `payload` каждого сигнала лежат `gate`, `weight` и `basketSize`.
