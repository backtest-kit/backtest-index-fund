# Индексный фонд: квартальная корзина с трендовым гейтом по BTC

## Что делает стратегия

Каждый календарный квартал это отдельная папка `content/q<n>_<yyyy>/` (`q1` = январь-март) с самодостаточным кодом: `main.strategy.ts` (стратегия и список тикеров квартала), `classes/YahooFinance.ts` (дневные свечи Yahoo Finance без ccxt) и `modules/backtest.module.ts` (адаптер биржи с маппингом `BASEUSDT` в `BASE-USD`, семплирование минуток из дневок через `getCandlesSampled` и трёхмесячный фрейм). В `classes/` рядом лежат и другие источники в том же формате фетчера (`BinanceFutures.ts`, `BinanceFunding.ts`, `UzSE.ts`), фондом они не используются. Общего кода между кварталами нет, папки штампуются копипастой из эталона.

Правила фонда, все константы в шапке `main.strategy.ts`:

- Депозит 1000 $ делится поровну между тикерами корзины квартала.
- Корзина квартала: топ-20 USDT-пар спота Binance по обороту за месяц перед началом квартала. Список известен до начала квартала, заглядывания вперёд нет. Исключены стейблкоины, плечевые токены, обёртки BTC/ETH и листинги моложе 90 дней.
- Гейт: доля окон 20, 25, 30, 35, 40, 45 дней, на которых BTC вырос. Это экспозиция корзины от 0 до 1, остаток депозита уходит в PAXGUSDT (золото).
- Каждая позиция открывается на первом тике квартала и закрывается по времени на конце фрейма: `minuteEstimatedTime` равен 92 дням минус минута, больше любого квартала, а ядро закрывает всё открытое на `endDate` фрейма с причиной `time_expired`. Перезахода внутри квартала нет, кроме случая стопа: стоп −50% за три месяца достижим (сентябрь 2020, май и ноябрь 2022), после него символ перезаходит на следующем тике с гейтом этого дня и держит до того же конца фрейма. Тейк +500% технический.
- Свечи дневные с Yahoo Finance, по одному запросу на тикер; минутки для симуляции семплируются из дневного бара, внутри дня движения нет, позиции оцениваются раз в сутки (`watchInterval: "1d"` в схеме фрейма, тики стратегии остаются часовыми). Дыры выходных и битые бары Yahoo (нули, выбросы) чинит ядро в `getCandlesFilled` плоской свечой по соседям, пороги `CC_GET_CANDLES_PRICE_ANOMALY_THRESHOLD_FACTOR` и `CC_GET_CANDLES_MAX_ANOMALY_STREAK`. Список тикеров квартала определяет, какие ряды будут скачаны. Mongo хранит только сигналы и состояние, свечи в него не пишутся.

Ограничение движка: общего депозита между символами нет, каждый символ это независимый бэктест, вес задаётся через `cost` сигнала. `cost: 0` движок молча заменяет на 100 $, поэтому нулевая доля это `null` вместо сигнала.

## Подготовка

```bash
npm install
docker compose -f docker/mongo/docker-compose.yaml up -d
docker compose -f docker/redis/docker-compose.yaml up -d
```

Mongo и Redis обязательны: `config/loader.config.ts` ждёт их подключения до загрузки стратегии, хотя свечи в Mongo больше не пишутся. Пароль Redis из `docker/redis/docker-compose.yaml` задаётся переменной `CC_REDIS_PASSWORD` в `.env`.

## Пересборка списков тикеров и папок кварталов

```bash
node scripts/common/build_universe.mjs --top 20 --from 2020-09 --to 2026-09
node scripts/common/resolve_yahoo_tickers.mjs
# повторять две команды выше, пока сборщик не перестанет печатать список непроверенных монет
node scripts/common/verify_yahoo_tickers.mjs
# если сверка отвергла монеты - снова цикл сборщик/резолвер до сходимости
node scripts/common/generate_months.mjs --source content/q4_2020
```

Сборщик качает месячные свечи всех USDT-пар Binance (кэш в `tmp/`, `--refresh` обновляет) и ранжирует их по обороту в `scripts/common/universe.json`. Резолвер находит для каждой монеты из корзин тикер Yahoo: обычно `BASE-USD`, для одноимённых токенов тикер с числовым суффиксом через поиск Yahoo, переименования заданы явно, а монеты без котировок на Yahoo помечаются `null` в `scripts/common/yahoo_tickers.json` вместе с датой начала истории. Сборщик исключает из корзины месяца монеты с `null` и монеты, чья история на Yahoo начинается позже чем за неделю до начала месяца; их места занимают следующие по обороту, которые тоже надо проверить, поэтому две команды повторяются до сходимости, обычно два-три раза. Сборщик завершается с кодом 2, пока в корзинах есть непроверенные монеты, а генератор отказывается штамповать такой месяц. Это не формальность: отсутствующий на Yahoo тикер в корзине роняет весь прогон месяца на первом тике.

Сверка `verify_yahoo_tickers.mjs` сравнивает закрытия Yahoo с месячными закрытиями Binance на входе и на конце каждого месяца, где монета стоит в корзине: прямой тикер `BASE-USD` может принадлежать другой монете с тем же именем (так было с `APE-USD`, `ARB-USD`, `TON-USD`), деноминация ломает ряд, а у `OP-USD` до октября 2022 лежит кусок чужой истории. Монета отвергается и получает `null`, если расходится больше половины сравнённых месяцев, причины в `scripts/common/yahoo_tickers_rejected.json`. Единичные плохие месяцы пишутся в поле `badMonths` записи, и сборщик не берёт монету в эти месяцы. Плохим считается и месяц, на краю которого Binance торгует, а у Yahoo цены нет: так рвутся ряды на миграциях токенов (DYDX в ноябре 2023), и ядро на такой дыре останавливает прогон вместо того, чтобы рисовать плоский рынок. Точечная перепроверка: `--only SYM1,SYM2`. Туда же попадают месяцы с ценой ниже 1e-5 долларов: Yahoo хранит семь знаков, и у PEPE по 8e-7 шаг цены равен 12%, такие ряды для доходностей непригодны. Генератор берёт из `universe.json` месяцы, открывающие календарный квартал (январь, апрель, июль, октябрь), копирует эталонную папку в каждый квартал, подставляя блок `BASKET:BEGIN..BASKET:END` в стратегии, блок `TICKER_OVERRIDES` и трёхмесячный фрейм в модуле биржи, пропускает кварталы, не закончившиеся к сегодняшнему дню, копирует `classes/` и переписывает раннеры `scripts/linux/run_strategy.sh` и `scripts/win/run_strategy.bat`.

Чтобы изменить стратегию, правьте эталон `content/q4_2020/main.strategy.ts` и запускайте генератор заново.

## Прогон

Один квартал:

```bash
npm start -- --backtest --entry ./content/q4_2020/main.strategy.ts
```

Все кварталы подряд:

```bash
bash scripts/linux/run_strategy.sh
```

Отчёт квартала: `content/<квартал>/dump/report/backtest.jsonl`, строки `opened`, `active` и `closed` по каждому сигналу; `closeReason: "time_expired"` это штатный выход на конце квартала, `stop_loss` это срабатывание −50%. В `payload` каждого сигнала лежат `gate`, `weight` и `basketSize`. Каждый квартал завершает процесс через `kill()` с ненулевым кодом, раннеры это не считают ошибкой.

Сводка по всем кварталам одной командой:

```bash
node scripts/common/summarize_reports.mjs
```

Таблица по кварталам и годам: сделки, нетто, оценка издержек движка, брутто, вклад PAXG, диапазон гейта; кумулятивный P&L с просадкой; и список закрытий не по времени, каждое из которых повод проверить данные за ним. Квартал с числом `opened`, не равным `closed`, оборван, его надо перепрогнать.
